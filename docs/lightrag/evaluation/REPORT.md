# LightRAG V1 小语料检索与回答表征

本报告对应新功能验收，不是公开 benchmark、线上生产流量或医疗正确性验证。
语料、问题和评分规则在模型调用前冻结；原有项目评测文件未修改。

## 协议与失败基线

- 两个领域、六份原创合成资料、十二个固定问题；每领域三份资料，含单文档、
  跨文档及无答案问题。检索报告 Top-3 来源。
- 对比现有 BM25 + Dense + RRF 与 LightRAG mix；同一 Embedding 服务和资料范围，
  本次配置未启用 reranker。
- 聊天模型：`deepseek-v4-flash`；Embedding：`BAAI/bge-large-zh-v1.5`，1024 维。
- 首次真实运行因适配器把不支持的 `timeout` 参数传给 `openai_embed`，在入库阶段
  失败，零题完成。记录保留在 `run1-failed/STATUS.json`。修复使用支持的客户端
  配置和原始 Embedding 回调，不改模型、语料、问题或评分，另行运行。

## 修复后的检索运行

`run2-retrieval/results.json`：十二题完成，其中十题有答案。

| 指标 | 现有混合检索 | LightRAG mix |
| --- | ---: | ---: |
| 必需来源 Recall@3 均值（10 题） | 1.000 | 1.000 |
| 平均查询时间 | 160 ms | 3823 ms |
| 无答案题仍返回来源（2 题） | 2 | 2 |

每个领域只有三份资料，Top-3 来源召回存在明显的上限效应；不能用这些结果说明
GraphRAG 普遍优于或等于现有检索。两种检索都会对无答案问题返回相似材料，是否
弃答还需要回答阶段判断。检索接口没有暴露完整 provider usage，因此相应消耗
记录为不可用，不能写成零消耗。

## 共享回答流程

独立冻结的 `answer_protocol.json` 使用同一个单次生成提示和参数消费上述实际检索
结果：temperature=0、max_tokens=2048、无自动重试，共 24 次调用。这不是生产
Autonomous 多轮工具执行评测。

| 指标 | 现有混合检索上下文 | LightRAG 上下文 |
| --- | ---: | ---: |
| 回答调用数 | 12 | 12 |
| 伪造引用 ID 数 | 0 | 0 |
| 必需引用覆盖均值 | 0.950 | 0.950 |
| 无答案题正确弃答 | 2/2 | 2/2 |
| 手工定义概念正则覆盖均值 | 0.733 | 0.933 |
| 单次生成平均时间 | 1628 ms | 1169 ms |
| Provider 返回的总 token 数 | 8462 | 7356 |

概念正则覆盖是词项层面的诊断，不能当作事实正确率、语义评审或显著提升。序列
调用、缓存和样本规模也限制了延迟比较。逐题答案、实际引用、finish reason、
provider 返回的 token usage 和耗时保存在 `answer-run1/results.json`。
Provider 未返回货币成本，因此没有填写或估算金额。

## 工程证据与边界

- 真实 SDK/数据库合同、真实 HTTP 联调和离线备份恢复使用确定性模型替身，验证
  执行链路、隔离、来源、纠错和恢复，不计入上述真实模型结果。
- `citation_ids_valid` 证明引用来自本轮授权证据，不证明每项回答事实都被原文蕴含。
- 原始失败、修复后的检索结果和后续回答结果分别保存，不合并为一次实验。
- 冻结清单和命令入口见 `evaluation/knowledge/` 与 `scripts/evaluate_knowledge*.py`。
